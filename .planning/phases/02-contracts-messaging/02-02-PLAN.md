<objective>
Declare the RabbitMQ topology in KargoNet.Messaging: topic exchange `kargonet.shipments`, main queue `shipments.main` (routing key `shipment`), retry queue `shipments.retry` (routing key `shipment.retry`, 5s TTL, dead-lettered back to the exchange on `shipment`), and DLQ `shipments.dlq` (routing key `shipment.dead`). The topology is captured as a data-only `TopologySpec` so its names, keys, and arguments are unit-testable with no broker; a thin `DeclareAsync(IChannel)` applies the spec to a real channel (the live declaration itself is exercised in Phase 6).

Purpose: This is the whole delivery/rel routing graph that MSG-01 requires. Getting the names, binding keys, and dead-letter arguments exactly right here means the retry→main and exhausted→DLQ paths work the moment a real broker is attached in Phase 6.

Output: RabbitMQ.Client package reference on KargoNet.Messaging, the topology spec + declarer, and broker-free unit tests proving the exact topology.
</objective>
