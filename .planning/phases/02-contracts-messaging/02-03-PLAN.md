<objective>
Build the publisher in KargoNet.Messaging with publisher confirms: `MessagePublisher.PublishAsync(string routingKey, ReadOnlyMemory<byte> body, IDictionary<string, object?>? headers)` publishes to the fixed topic exchange `kargonet.shipments` and awaits the broker's confirm, propagating a failure when the publish is not confirmed.   <action>
Create the publishing files under `src/BuildingBlocks/KargoNet.Messaging/Publishing/` in `KargoNet.Messaging.Publishing`. RabbitMQ.Client 7.x is already referenced (added by plan 02-02); do not add another package.

1. `PublishOutcome.cs` — a small public readonly struct with a single `bool IsConfirmed` (and optionally the publish id). This is OUR type, decoupled from RabbitMQ's `PublishResult`, so tests can construct it freely.

2. `IOutboxChannel.cs` — the thin seam. Single member: `Task<PublishOutcome> PublishAsync(string exchange, string routingKey, ReadOnlyMemory<byte> body, IDictionary<string, object?>? headers)`. This is the ONLY broker surface the publisher depends on.

3. `MessagePublisher.cs` — the publish helper. Constructor takes an `IOutboxChannel`. Expose exactly `Task PublishAsync(string routingKey, ReadOnlyMemory<byte> body, IDictionary<string, object?>? headers)`. Internally it:
   - calls the seam with the fixed exchange `RabbitTopology.Exchange` (`kargonet.shipments`), the caller's routing key, body, and headers;
   - awaits the returned `PublishOutcome`;
   - if `IsConfirmed` is false, throws a descriptive `PublishNotConfirmedException` (add a small exception type) so the caller can react; if confirmed, returns normally.
   The confirm handling is the "thin seam" logic — pure enough to unit-test with a fake channel.

4. `RabbitOutboxChannel.cs` — the real adapter implementing `IOutboxChannel` over RabbitMQ.Client 7.x `IChannel`: it calls `channel.PublishAsync(...)` (which uses publisher confirms) and maps the library's confirm result into a `PublishOutcome`. This is the live path; it is compiled and wired but only exercised against a real broker in Phase 6.

Keep this task focused on publishing — no consumer, no retry, no DLQ, no envelope types.
