<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form -> portal | Untrusted user input (tracking number, description, destination) crosses from the form into controllers and is reflected in rendered HTML |
| portal -> Shipment/Tracking APIs | The portal forwards user-supplied tracking numbers into upstream API URLs/queries; upstream JSON is rendered into views |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | `TrackController` / `ShipmentsController` rendered views | medium | mitigate | All user-derived values render through Razor `@` expressions (auto-encoded); the tracking number in URLs is built with `Uri.EscapeDataString`; no `Html.Raw` anywhere in new views |
| T-05-02 | Tampering | `PortalApiClient` upstream calls | medium | mitigate | Tracking numbers are interpolated into absolute URIs only; 404 maps to a null/view state and 5xx/timeout to a caught `ApiRequestException` — unhandled upstream exceptions never reach the response pipeline as 500 stack pages in the three portal actions |
| T-05-03 | Information Disclosure | `TrackController` timeline rendering | low | accept | `payloadJson` is parsed defensively; parse failures render the `eventType` text only, never raw payload bytes or exception details |
| T-05-SC | Tampering | NuGet package install (test project) | high | mitigate | `Microsoft.AspNetCore.Mvc.Testing 10.0.15` is the exact version already pinned by `tests/KargoNet.Tracking.Tests` in-repo (no new, unpinned packages); `dotnet list package tests/KargoNet.Portal.Tests` must show only the mirrored, version-locked set before the first test run |
</threat_model>
