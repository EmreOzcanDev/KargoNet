<objective>
Stand up the persistence layer in Shipment.Api: the `Shipment` and `OutboxMessage` entities, the `ShipmentDbContext` (Npgsql provider, statuses stored as strings, unique index on `TrackingNumber`, composite index on `OutboxMessage (Status, CreatedAt)`), a design-time `IDesignTimeDbContextFactory`, and the `InitialCreate` migration generated by `dotnet ef` with no live database. Also add `Microsoft.EntityFrameworkCore.InMemory` to the test project so plans 03-02/03-03 can unit-test every EF behavior with no live Postgres.

Purpose: SC1/SC3 require the shipment row and its outbox row to be atomic — that starts with a correct model, an index the publisher's hot poll (`WHERE Status = Pending ORDER BY CreatedAt`) can use, and a migration that runs in Phase 6's compose stack. The InMemory test plumbing lands here so the later plans never block on DB availability.

Output: Two entity files, `ShipmentDbContext` + design-time factory, the `InitialCreate` migration, pinned EF Core/Npgsql package references, and an InMemory-based smoke test of the model.
</objective>
