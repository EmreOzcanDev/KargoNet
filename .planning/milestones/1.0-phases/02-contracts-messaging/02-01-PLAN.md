<objective>
Stand up the cross-service event contract in KargoNet.Contracts: the `EventEnvelope` wrapper, the two typed payload records (`ShipmentCreatedPayload`, `ShipmentStatusChangedPayload`), and the `EventSerializer` that (de)serializes them with System.Text.Json in camelCase. This is the message shape that the Phase 2 publisher sends and the consumer base deserializes, so it lands first and is proven end-to-end by a serialize→deserialize round-trip before any broker code exists.

Purpose: The envelope is the durable JSON contract — it is serialized into RabbitMQ and persisted in the DLQ, and Phases 3-4 deserialize it. Locking the field names/shapes here means later phases never migrate in-flight or dead-lettered messages.

Output: Four source files in KargoNet.Contracts/Events plus a xunit test class proving the round-trip and the camelCase wire format.
</objective>

  <action>
Create the four contract files under `src/BuildingBlocks/KargoNet.Contracts/Events/` in the `KargoNet.Contracts.Events` namespace. No new package references — System.Text.Json is in the .NET 10 BCL.

1. `EventEnvelope.cs` — a `record` with exactly: `Guid EventId`, `string EventType`, `DateTimeOffset OccurredAt`, `System.Text.Json.JsonElement? Payload`. This is the wire wrapper; keep property names exactly as named (they serialize to the camelCase wire form `eventId`, `eventType`, `occurredAt`, `payload`).

2. `ShipmentCreatedPayload.cs` — a `record` with `string TrackingNumber`, `string Description`, `string Destination`.

3. `ShipmentStatusChangedPayload.cs` — a `record` with `Guid ShipmentId`, `string TrackingNumber`, `KargoNet.Contracts.Models.ShipmentStatus FromStatus`, `KargoNet.Contracts.Models.ShipmentStatus ToStatus`. The status fields are the `ShipmentStatus` enum (referenced by name, not a raw int), per the locked decision.

4. `EventSerializer.cs` — a static class with a fixed `JsonSerializerOptions` instance (camelCase naming, `JsonSerializerDefaults.Web` is acceptable as long as property names come out camelCase). Expose two methods:
   - `byte[] Serialize<TPayload>(EventEnvelope<TPayload> envelope)` — serializes the envelope to UTF-8 bytes.
   - `EventEnvelope<TPayload> Deserialize<TPayload>(ReadOnlySpan<byte> utf8)` — parses bytes back and reconstructs the typed payload from the `Payload` JsonElement into `TPayload`.
   The envelope must be generic over its payload type so the same `EventEnvelope` shape carries `ShipmentCreatedPayload` or `ShipmentStatusChangedPayload`. Serialize the payload into the `Payload` JsonElement on the way out and re-project it back on the way in (use `JsonElement` + `GetProperty`/`Deserialize<TPayload>` on the payload element, not the whole envelope, so the envelope fields and payload fields are handled separately).

Keep it a pure data + serializer file set — no RabbitMQ, no IChannel, no hosting. Do NOT add a third-party serialization package.
